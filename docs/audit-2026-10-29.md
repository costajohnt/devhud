devhud (`costajohnt/devhud`, checkout `~/dev/simon-dash`) @ commit `79ee2c6`, branch `master`, the commit published as `devhud@0.1.0`. ~19.6k tracked lines (lockfiles, images and fonts excluded), 27 test files. Four parallel read-only review streams (correctness, security, tests, architecture), then a fresh adversarial verify pass on every Critical/High finding.

## Critical

None found. Five findings were raised as High; on independent verification two held as High (H1, H2), two were confirmed but rated Medium (M1, M25), and one was refined to Low (the CLI transport-test flake). ## High

### H1. **A card can never stay pinned in In QA: the pin is wiped on the next refresh**
`server/classify.ts:178-183` clears `cs.override` whenever the card's status *is* In Test (or Done), on every refresh. It is a status check, not a transition check. The later `lastStatus` rule (`classify.ts:~191`, #61) already clears a pin when the status actually changes, so the only remaining effect of `:180` is deleting pins set while the card is already In Test, which is exactly the documented `in_qa` workflow (`README.md:231` "Manual-move destination for cards actively being tested"; `docs/ARCHITECTURE.md:134`; In QA is a drop target in `web/src/board.tsx:60` and a move option in `web/src/detail.tsx:6`). The Done half is dead in production: `refresh.ts:137-154` routes Done cards off-board before `classifyCard` runs. Verified by probe: an In Test card with `override: 'in_qa'` and `lastStatus: 'In Test'` comes back `bucket=qa_ready override=null`, so a dragged card shows in In QA until the next tick, then bounces back. No test covers an In Test card pinned to `in_qa`; `classify.test.ts:163` locks in the clearing with a `waiting_review` pin and no `lastStatus`. Fix: delete `classify.ts:178-183` and let the `lastStatus` transition rule clear pins; update `classify.test.ts:163` to seed `lastStatus`, and add an In Test + `in_qa` survival test.

### H2. **Acks never stick on a To Do card that has a linked PR**
`server/refresh.ts:118-121` resets `cs.ackedReasons = null` for cards that leave the board, but tests `isTodo(card)` alone, while `refresh.ts:130` only routes a To Do card off-board when it has no PR (`isTodo && !pr`). A To Do card with an open PR therefore stays on the board and is classified, yet its acks are wiped before `classifyCard` on every refresh. `state.ownPrs` cannot restore them: a card ack (`actions.ts:163`) writes only `cs.ackedReasons`, and `ownPrs` is rewritten at `refresh.ts:170-172` after the wipe. Reproduced by probe: In Progress control `ack ci_failing` → after refresh `[]`; same card in To Do → after refresh `['ci_failing']`, back in Needs Attention, so the TODO entry and its desktop notification return every tick. Fix: make the reset match the routing, `isCanceled || (isTodo && !linked.get(card.key)) || isBlocked || isDone` (or move the `pr` lookup above the reset).

## Medium

- **M1.** **Acking can permanently swallow a comment that landed during the refresh** (verified; flagged High by the correctness stream, rated Medium on verify). `server/actions.ts:150-152` uses `state.snapshot.updatedAt` as the "seen" horizon, but `buildSnapshot` stamps it at the end of the build (`refresh.ts:290`), after the Jira read (`refresh.ts:421`), the PR fetch, enrichment batches (200ms pauses, throttle retries up to `THROTTLE_BUDGET_MS = 90_000`) and the review-request search. A comment created inside that window is not in the snapshot, yet `ack`/`move` (`actions.ts:118,161,162,178,207`) set `lastSeen*` past it, and `after()` (`classify.ts:13`) rejects it on every later refresh: silent, permanent loss of the "someone is waiting on you" signal. Window is seconds normally, up to ~90s when throttled, the whole outage on a stale fallback. Fix: record `dataAsOf` before the first fetch, store it on the snapshot, use it as the ack horizon (per-source read times to also cover fallbacks).
- **M2.** **With `autoTransitionMerged` on, a QA rejection the board never observed gets undone.** `server/classify.ts:141,148` / `server/writeback.ts:402-411`: `reachedTestAt` is stamped only when a refresh happens to see the card In Test/Done, so In Test → back to In Progress between ticks (laptop asleep, server down, under 2 min) leaves no stamp and `merged_not_in_test` fires on the old merge; the live re-check only confirms the status is still pre-test. Fix: skip the auto-transition when `card.updatedAt > pr.mergedAt`, or read the Jira changelog. (unverified)
- **M3.** **Loopback API has no authentication.** `server/index.ts:64,269`, `server/ops.ts:29-30`: state and pid files are 0600, but any local process that can reach 127.0.0.1:port can GET `/api/data` and, with `writeEnabled`, POST `/api/write` as the user; `guardHost` only stops browsers. Conversely the CLI/MCP trust whatever answers on `config.port`, so a process squatting the port while devhud is down can feed the MCP client forged snapshots and receive write bodies. Fix: random token in a 0600 file under `HOME`, required on every `/api/*` request and sent by `ops.ts`. (unverified)

## Security summary

The fixes from the 2026-08-02 audit all still hold against current code: the prototype-pollution guards (`actions.ts:97`, null-proto `state.cards`, `PR_REF_RE` keys), the Host check on every `/api/*` route including SSE, JSON-only POSTs with no CORS, 0600 state/pid/config writes, static-path containment, and load-time validation of everything that reaches JQL or GitHub URLs. The 0.1.0 tarball holds only `dist/`, `web/dist/`, README, LICENSE and the example config; the release workflow is tag-only, master-only and SHA-pinned. The open exposure is local and agent-side: the loopback API has no token (M3), MCP write tools let third-party text steer real writes with only a prompt note in the way (M4), and `init --force` can briefly expose tokens (M14). Smaller items: config parse errors can echo a token fragment, `baseUrl` isn't forced to https, and the publish job builds while holding the OIDC token (all Low).

## Test quality

554 tests across 27 files, stable across 5 sequential, 24+ concurrent and 6 shuffled-order runs. Mutation probing (59 mutants by the tests stream, more on verify) shows the classifier, write-back gates, state persistence, Jira pagination, GitHub throttling, queue priority, review-request dismissal and web notify/queue logic are well defended. The thin spots cluster around the newest code, the state that crosses paths:

1. Per-reason Jira-comment dismissal has no test at all (M25).
2. ownPrs ↔ card sync and degraded card-less PR handling (M6); PR-ref multi-reason acks (M7).
3. Two tests whose names promise more than they check (M5 whole-fetch degradation, M10 JSON-only refresh).
4. Untested surfaces: `mcp/index.ts` (M9), `server/paths.ts` installed-home default (M13), `init` beyond the happy path (M14), `serve` signal forwarding outside CI (Low).
5. Environment leaks into results: `DEVHUD_DEMO` in the shell (M12) and stale `.claude/worktrees` copies (M11).
6. Host-guard coverage is narrower than the guard (M8). CI is Ubuntu-only for a macOS-first tool (Low).

## Refactoring map

1. **Docs and descriptions pass (S, no risk):** MCP tool descriptions (M23), README packaging + `todo_list` (M24), ARCHITECTURE/API drift and stale comments (Low).
2. **Test hygiene (S):** vitest config + oxlint ignore + `.gitignore` for `.claude/` (M11), clear demo env in setup (M12), `viaServer` injectable in `run()` (Low).
3. **Deletions (S):** Simon/jira-dash aliases, dead CSS, dead params/exports, MCP version string, duplicate `DEFAULT_STATUSES` (Low).
4. **Single sources of truth (S/M):** qualify repos once in `loadConfig` (M18), `failedRepos` from `fetchPrs` (M15), web `import type` from server types (M17).
5. **Reason registry then shared routing (M):** one `REASONS` table (M19), then `routeBucket()` shared by `classifyCard` and `classifierDest` (M16).
6. **Split `refresh.ts` (M):** extract the GitHub phase and builders, pass `linked` through, one prune step that also prunes `state.cards` (M22, M20), move last-known-good inputs out of the snapshot.
7. **Slim the wire payload (M):** chart window + capped Done page on SSE, summary `board_status` (M21).
8. **Sources as plugins (L):** generalize `QueueEntry.kind` into `source` with a per-source ack handler table, replacing the special cases in `actions.ts:100-125`. Prerequisite for Slack/email.
