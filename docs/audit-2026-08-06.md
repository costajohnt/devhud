# simon-dash audit (2026-08-06)

Repo `~/dev/simon-dash` @ commit `bbff95b`, branch `live-sse` (worktree), audited across 4 parallel review streams (correctness, security, tests, architecture/docs) with adversarial verification of every CRITICAL/HIGH finding. Size: 17,292 tracked lines. Baseline: `npm test` (tsc --noEmit + vitest) green — "Tests  211 passed (211)", duration 1.47s. No lint script is configured in package.json (finding-in-waiting, see Refactoring map).

## Critical

None.

## High

### H1. Scheduled refresh loop has zero test coverage
`server/index.ts:192-203` The branch's headline feature — the setInterval tick driving refresh → saveState → broadcast, plus the catch that keeps the loop alive through a Jira/GitHub outage — is dead code under test. Verified: zero `useFakeTimers` across all 12 server test files, and no test sets `refreshIntervalSeconds`, so every test server falls back to the 120s default and a tick can never fire inside a test run. The `clearInterval` on close executes incidentally via the SSE-shutdown test but is never asserted. The loop *felt* covered because its body is structurally identical to the well-tested POST /api/refresh handler, but the timer path and the error-swallowing catch are distinct code. Fix: one test with `vi.useFakeTimers()` + mocked `./refresh.ts` and `refreshIntervalSeconds: 1`, asserting an SSE client receives a broadcast on tick and that a rejecting tick doesn't kill subsequent ticks.

### H2. Client half of the SSE feature is entirely untested
`web/src/use-data.ts:25-108` The onmessage seq-supersede, the `updatedAt` dedup gate that stops confetti replay, the get-vs-refresh race guard, and `act()`'s error-body parsing — exactly the logic the file's own comments say bugs lived in — have zero coverage. Verified: `vitest list` shows the only web tests are 8 pure-function tests in `chart-panel.test.ts`; no vitest config, no jsdom/happy-dom/@testing-library anywhere, so nothing can render a Preact hook or provide `EventSource`. The barrier is missing tooling, not impossibility. Fix: extract the event-application decision ("apply this snapshot? fire onRefreshed?") into a pure function tested in node — cheaper than adding a DOM environment and covers the load-bearing logic (see also M8, a live bug in this exact gate).

### H3. Stale refresh payload is broadcast to all SSE clients, defeating the refreshSeq gate
`server/index.ts:116-119,194-196` (with `server/refresh.ts:210-217`) The refreshSeq gate stops a losing (stale) refresh from writing `state.snapshot` — but `refresh()` returns its payload unconditionally, and both broadcast call sites broadcast that returned value, not `state.snapshot`. Verified trace: manual refresh A (seq 1, slow) and interval refresh B (seq 2, fast) overlap; B wins, writes state, broadcasts fresh; A loses the state write but its `broadcast(payloadA)` lands last — every connected tab reverts to stale data for up to `refreshIntervalSeconds` (120s). The correct pattern (`broadcast(state.snapshot)`) already exists in the same file at the /api/action and /api/write handlers. Refinement from verification: `send(200, payload)` on the manual-refresh response leaks the same stale payload to the requesting tab. Root cause: the win/lose decision lives inside `refresh()`, the broadcast decision in callers with no visibility into whether their payload won. Fix: use `state.snapshot` for both broadcast and response at both call sites (always non-null after any `refresh()` resolves).

## Medium

- **M1.** Write-back targets validated for syntax, not scope — `server/writeback.ts:192-196`. KEY_RE/REPO_RE answer "well-formed?", but the MCP surface's real trust question is "is this a resource this dashboard manages": a prompt-injected agent with `writeEnabled: true` can transition/comment ANY Jira issue or comment on ANY repo the tokens reach (the codebase itself models board text as attacker-adjacent, `mcp/handlers.ts:35`). Fix: require `key` to start with `projectKey + '-'` and `repo` ∈ configured `org/repos` list. (unverified)

- **M2.** `web/src/board.tsx` (259 lines) and `app.tsx` (243 lines) have no tests at all — drag-and-drop moves, optimistic UI, and routing ride on manual testing; same missing DOM test environment as H-series SSE gaps. Server-side move validation softens the blast radius. Fix: same environment investment; test the drop handler's payload construction at minimum. (unverified)
- **M3.** `web/src/chart-panel.test.ts:20-31` — year-rollover test is near-tautological: `years.size >= 1` cannot fail, and the adjacency arithmetic that would catch a rollover bug runs only on `lastNMonths(6)`, which crosses a year boundary only when the suite runs January–May. Fix: run the adjacency loop over `lastNMonths(13)`. (unverified)
- **M4.** `server/cli.test.ts:14`, `transport.test.ts:13`, `mcp/handlers.test.ts:12` — hardcoded "nothing listens here" ports (39217-39299 range); if any local process binds one, direct-mode tests silently flip into via-server mode against a stranger's server. Fix: allocate via `listen(0)` then close, or inject the transport probe. (unverified)
- **M5.** `server/index.ts:236` — the pid-file writer is untested while every split-brain test hand-crafts its own `{ pid, port, startedAt }` literal; a field rename would pass 211 tests and break the split-brain guard in production. Root cause: the writer lives in the untestable main block. Fix: hoist `writePidFile`/`readPidFile` into transport.ts, test the round-trip. (unverified)
- **M6.** `server/jira.test.ts:58-86` — the only `fetchJiraCards` test returns the search payload for any URL not containing `/comment?`, so a wrong endpoint, missing auth header, or broken JQL encoding all pass. github.test.ts already throws on unexpected URLs; jira.test.ts should match. (unverified)

- **M7.** Non-reentrant `console.log` monkeypatch can permanently disable server logging — `server/writeback.ts:243-251`. Two concurrent POST /api/write requests interleave at the awaited post-write refresh: B captures A's noop as "original", restores it last, and `console.log` stays a noop for the rest of the process. The same pattern is safe in cli.ts/mcp only because those are single-invocation processes. Fix: pass a `quiet` option into `refresh()` instead of patching the global. (unverified)
- **M8.** Confetti/toast replays on every page load and reconnect — `web/src/use-data.ts:85,99-102`. `lastEventAt` starts `undefined`, so the SSE connect replay always looks like a "changed" updatedAt and fires `onRefreshed`; `newlyMerged` stays non-empty (and persisted) until the next real refresh, so each reload/reconnect in that window replays the celebration. Fix: on the first message record `updatedAt` without firing. (unverified)
- **M9.** Concurrent refreshes clobber `state.lastCards`/`state.lastPrs` with older data — `server/refresh.ts:171,205`. The seq gate protects only `snapshot`/`lastRefreshAt`; the last-known-good caches (the outage fallback) are assigned unconditionally at await-separated points, so a slow stale refresh overwrites fresher caches after the fact. Fix: move those writes inside the seq-win block. (unverified)
- **M10.** Dual-transport orchestration duplicated wholesale between CLI and MCP — `server/cli.ts:103-259` + `mcp/handlers.ts:38-207`. The semantic core is shared (`applyAction`/`performWrite`/`refresh`), but probe → fetch-with-error-mapping vs direct-mode guard/save orchestration is written twice near line-for-line; `transport.ts` extracted primitives one layer too low. Fix: move the four `do*` operations into transport.ts (or ops.ts), CLI keeps argv parsing + formatting; removes ~120 lines and two hand-synced `saveBlockedError` copies. (unverified)
- **M11.** Full snapshot broadcast every tick even when nothing changed — `server/index.ts:192-202`. `buildSnapshot` stamps a fresh `updatedAt` unconditionally, so there is no "content unchanged" signal; every tab re-renders the whole board every 120s, and the client's `lastEventAt` gate treats every tick as a real refresh. Fix: serialize snapshot minus `updatedAt`, compare with previous, skip broadcast (send an SSE comment as heartbeat) when identical. Cheap 80% of diffing; per-field patches not worth it at this payload size. (unverified)
- **M12.** No conditional requests (ETag/If-None-Match) in the GitHub client — `server/github.ts:101-108`. Per tick: R list calls + 4×P enrichment calls; 10 repos with 15 linked PRs ≈ 2,100 req/hr of the 5,000 budget, mostly byte-identical responses. GitHub 304s are free. Fix: module-level `Map<path, {etag, body}>` in `gh()`, send `If-None-Match`, serve cached body on 304. Webhooks would kill polling entirely but need a public endpoint — wrong tradeoff for a loopback tool. (unverified)
- **M13.** `setInterval` refresh can overlap itself once a sweep outlasts the interval — `server/index.ts:192`. Fixed cadence measures from tick start; `refreshSeq` protects ordering, not duplicate API spend, which compounds with M12 as repo count grows. Fix: self-rescheduling `setTimeout` armed after each completion. (unverified)
- **M14.** No Node version requirement stated anywhere — README/package.json. The repo runs on native type stripping (Node ≥22.6, unflagged ≥22.18); Node 20 users hit `ERR_UNKNOWN_FILE_EXTENSION` at setup step 3 with no hint. Fix: `"engines": {"node": ">=22.18"}` + one README line. (unverified)
- **M15.** Nested interactive control inside `role="button"` — `web/src/board.tsx:227-246`. Each row is a button containing a real `<a>`; ARIA forbids interactive descendants of button roles, so screen readers flatten the row and the PR link becomes unreachable. Fix: scope button semantics to the key/summary span (or listbox/option + `aria-selected`), leave the row a container. (unverified)
- **M16.** Detail panel: no focus management, no Escape — `web/src/detail.tsx:25-34`. Keyboard users who activate a row must tab through the whole remaining board to reach the panel; close restores nothing. Fix: focus panel on open (`tabIndex={-1}`), Escape → close, return focus to originating row, `role="complementary"` + label. (unverified)

## Low (selected)

- `server/cli.test.ts:190`, `transport.test.ts:22` — pid 999999 as "guaranteed dead" is macOS-only truth (Linux pid_max reaches 4194304); flaky on Linux CI. Fix: spawn and reap a child, use its pid.
- `server/server.test.ts:461` — SSE reader `next()` has no timeout; a dropped broadcast becomes a vitest-global-timeout hang instead of an assertion failure. Fix: race against a short rejection timer.
- `server/github.test.ts:45-120` — read-path mocks never assert the bearer token or Accept headers; a dropped token would pass tests and 403 only in production. Fix: assert `init.headers` once per function.
- `server/index.ts:20-23` — `readBody` accumulates the POST body with no size cap; any local process can balloon memory. Fix: abort past ~1 MB.
- `server/jira.ts:28` — `projectKey`/`accountId` interpolated into JQL unescaped; self-owned config, so injection needs the victim editing their own file, but a stray quote silently rewrites the query. Fix: strict regexes in `loadConfig`.
- `server/github.ts:117` — `org`/`repo` interpolated unencoded into the API path; a `/` or `?` in a configured repo name re-routes the Bearer-tokened request (in-host SSRF). Fix: validate `repos[]` against `^[\w.-]+$` at config load.
- `server/index.ts:78-81,109` — `sseClients` unbounded and `broadcast` ignores `write()` backpressure; a stalled consumer buffers every future snapshot in heap. Fix: cap clients (~32) and destroy on persistent backpressure.
- `web/src/board.tsx:245` — one `target="_blank"` link missing `rel="noopener noreferrer"` unlike all siblings; per-link convention drifted. Fix: add rel (or extract shared external-link component).
- `server/index.ts:174-176` — no `X-Content-Type-Options: nosniff` / CSP on static responses; no second layer if a string-escape ever regresses. Fix: add nosniff + `default-src 'self'`.
- `server/index.ts:79-82` — `broadcast()` fan-out has no per-client error isolation: a synchronous write throw on one torn-down socket aborts the loop for remaining clients and can 500 an already-saved refresh; no `'error'` listener on held-open responses. Fix: try/catch per client + no-op error listener.
- `server/refresh.ts:40` (with `github.ts:5-18`) — `prLog.closedAt` recorded as `updatedAt` because `mapPr` never captures GitHub's `closed_at`; post-close activity silently shifts closed PRs between chart months on every refresh. Fix: map `closed_at`.
- `server/refresh.ts:19-25` vs `classify.ts:20-29` — comment→`NewComment` mapping duplicated (both slice body to 300 chars independently). Fix: one shared helper.
- `web/src/chart-panel.tsx:28` — `PrLogEntry` re-declared locally, duplicating the inline shape in `web/src/types.ts:29`. Fix: export from types.ts.
- `server/types.ts:203` / `actions.ts:72` — `overrideAt` is stamped but never read anywhere; speculative "pinned since" data. Fix: surface it (detail panel "pinned Nd ago") or stop stamping.
- `docs/API.md:249`, `docs/ARCHITECTURE.md:7` — stale endpoint enumerations omit `/api/events`/`/api/write` (the dedicated sections are accurate; only the lists drifted). `docs/API.md:162` still says `refresh.js`/`classify.js`.
- `web/src/detail.tsx:119,124` — renders literal "Invalid Date" when Jira omits `createdAt`; server `iso()` can yield null but the client type says `string`. Fix: null-guard + fix type to `string | null`.
- `web/src/board.tsx:80-92` — successful moves are silent to assistive tech (only failures announce). Fix: one polite `aria-live` region.
- `server/cli.ts:122-128` / `mcp/handlers.ts:88-94` / `writeback.ts:243-252` — the `console.log`-silencing monkeypatch appears three times (see M7 for the server-path bug). Fix: `refresh({quiet})`.

## Security summary

Clean overall for a loopback-only, single-user tool. The request-side guards hold up under adversarial reading: guardHost covers every `/api/*` route including the new SSE endpoint, guardMutation's content-type CSRF gate is sound, the static-file prefix check defeats encoded traversal, the prototype-pollution guard covers the bracket-assignment sink, all four write paths funnel through the fail-closed `performWrite` gate, Preact's text interpolation escapes all Jira/GitHub-sourced strings (no raw-HTML sinks anywhere), and nothing logs tokens. The one real gap is M1: write-back validates shape but not scope, so with `writeEnabled: true` a prompt-injected agent can write to any Jira issue or repo the tokens reach — worth fixing before write-back sees daily use. The rest (body-size cap, config-value validation feeding JQL/URL construction, SSE client cap, nosniff/CSP) is hardening depth, all LOW.

## Test quality

Server-side discipline is genuinely strong: per-test server isolation, TOCTOU and prototype-pollution tests, a real concurrency test on the refresh sequence guard, split-brain pid-file scenarios. The weakness is concentrated in exactly the newest code: the scheduled refresh loop is dead code under test (H1) and the client SSE logic has zero coverage with no DOM test tooling even installed (H2) — and M8 (confetti replay) is a live bug sitting in that untested gate, proving the gap has teeth. Gaps ranked:

1. Server refresh loop tick + error-recovery path (H1) — fake timers + mocked refresh, ~1 test.
2. `use-data.ts` event-application logic (H2) — extract pure function, test in node.
3. Mock fidelity: jira.test.ts accepts any URL for its primary request (M6); github read-path mocks never assert auth headers.
4. Environment-dependent flakes: hardcoded "dead" ports (M4), macOS-only pid 999999 assumption.
5. Tautological year-rollover chart test (M3); SSE test reader hangs instead of failing on a dropped broadcast.

## Refactoring map

Sequenced, smallest/highest-payoff first:

1. **SSE correctness batch (H3 + M8 + broadcast isolation low)** — broadcast/respond `state.snapshot` at both call sites; first-message guard in `use-data.ts`; try/catch per client in `broadcast()`. ~15 lines total, fixes the only user-visible live bugs.
2. **Refresh loop robustness (M9 + M13 + M7)** — move `lastCards`/`lastPrs` inside the seq-win block; switch to self-rescheduling `setTimeout`; add `refresh({quiet})` and delete three monkeypatches. One file each.
3. **No-op broadcast suppression (M11)** — hash snapshot-minus-updatedAt, skip identical broadcasts. Unlocks calmer always-on-screen behavior.
4. **ETag conditional requests (M12)** — `Map<path,{etag,body}>` inside `gh()`. Biggest API-budget win, fully transparent to callers.
5. **Transport op extraction (M10)** — move the four `do*` operations into transport.ts, CLI consumes them. ~120 lines removed; do it before adding any new transport surface.
6. **Config validation batch (jira/github lows + M1 scope check)** — strict regexes on projectKey/accountId/org/repos at `loadConfig`, plus scope enforcement in `performWrite`.
7. **A11y pass (M15 + M16 + aria-live low)** — board row semantics, detail-panel focus contract, move announcements.
8. **Add a lint script** — no eslint configured; the per-link `rel` drift (board.tsx:245) is exactly what a linter catches.

## Feature opportunities (ranked)

1. **(S) Attention notifications over the existing SSE channel** — app.tsx already computes the needs_attention count per snapshot for the tab title; compare previous→next in that effect and fire the Web Notifications API. Turns leave-it-on-a-screen mode into something that works when the screen isn't visible. Purely client-side.
2. **(S) Time-to-merge chart** — `prLog` already stores `openedAt`/`mergedAt`; a "median days open at merge" series is derivable with zero new server work and would be the first flow metric (vs counts) in the app.
3. **(S) Unpin action** — `cardState.override` can be set but never cleared; only hand-editing state.json returns a card to classifier control. `type: 'unpin'` in `applyAction` + a small affordance in detail.tsx completes the override lifecycle, and finally gives `overrideAt` a reason to exist.
4. **(S) Comment history on merged cards** — mcp's tool description documents that `card_comments` on merged cards returns empty because `buildSnapshot` drops `itemComments` for `MergedCard`; the data is in hand at that line.
5. **(M) Change-aware broadcasts + last-changed indicator** — once M11's no-op suppression exists, the server knows *when* content actually changed; surface "last change 3h ago" distinct from "last checked 2m ago" in the header.

On "is there a better way to do live": the SSE architecture is right for this tool. Webhooks would eliminate polling but need a public endpoint — wrong tradeoff for loopback-only. The real upgrades are M11 (don't broadcast no-ops), M12 (make polls nearly free via 304s, which also lets you safely shorten the interval to ~30-60s), and M13 (no overlap under load). With those three, this is a proper live dashboard, not just a polling one.
