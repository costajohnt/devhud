## High

### H1. Auto-transition moves cards to In Test that must not move
Location: `server/writeback.ts:289-335`, `server/classify.ts:83-85`, `server/refresh.ts` (Jira fallback). **(verified)**

`merged_not_in_test` fires for any card whose linked PR is merged and whose status is not exactly In Test or Done. `autoTransitionMergedCards` then transitions every card carrying that flag. Its only extra checks are the config gate, the project prefix and the ack list. A probe run through the real `buildSnapshot` and then `autoTransitionMergedCards` transitioned all of these:

- **A To Do card.** A merged "prep for PROJ-1" PR keeps the card on the board, and it gets pushed straight to In Test.
- **A card QA rejected back to In Progress.** The old merged PR is still the linked PR. The ack was pruned while the card sat in In Test, so the flag fires fresh and the next tick undoes QA's rejection. #88 (merged beats closed) widens this, because a newer closed follow-up PR no longer hides the old merged one.
- **A card in a status after In Test** that Jira does not put in the Done category ("Ready for Release", "QA Passed"). It moves backwards to In Test.
- **Stale data during a Jira outage.** When the Jira fetch fails, refresh falls back to `lastCards`, and the probe with `errors.jira` set still fired. `transitionCard` reads the transitions available from the *live* status. On a permissive workflow that can reopen a card that was moved to Done after the last good fetch.
- **Retries.** A failed transition is retried on every tick (one GET plus an error log every 2 minutes) with no backoff.

Without auto-transition, the same `classify.ts` rule still produces false Needs Attention entries and desktop notifications for cards in post-In-Test statuses.

Fix:
- Skip the batch when `snapshot.errors.jira` or `errors.github` is set.
- Only transition from an allowlist of statuses (the review status or the In Progress category), never from the To Do category.
- Re-read the issue status right before the POST and require it to match the snapshot.
- Record the (card, PR number) pair in state so each merged PR auto-fires at most once, and remember failures.
- In classify, flag only if the card has never been In Test or Done since the merge (`cs.lastStatus` history or `mergedAt` vs. the last move out of In Test). Optionally add configurable "past In Test" statuses.

### H2. The #89 "base CI still running" fix has no effect
Location: `server/github.ts:96-117`, `server/classify.ts:64`. **(verified)**

While the base branch's checks are pending, `newCiFailures` returns `undefined`, and it does the same when a failing head check is missing from the base. Classify flags `ci_failing` whenever `pr.ciNewFailures?.length !== 0`. `undefined !== 0` is `true`, so the card is flagged anyway. Before #89, a pending base produced `[]` from the base and every head failure counted as new, which is the same outcome. So the commit changed the helper's return value without changing what the board shows.

Scenario: a PR's `test` check already fails on main. Main gets a merge and its CI restarts. For the whole base run the card jumps to Needs Attention and fires a desktop notification, then drops back. That is the exact symptom #86 reported.

Verification: `mapPr` + `classifyCard` with a finished, failing base gives `ciNewFailures: []` and `waiting_review`. With a running base it gives `undefined`, `needs_attention` and `['ci_failing']`. The #89 tests only check the helper's return value, never the classification, which is why this slipped through.

Fix: give "unknown" its own meaning and have refresh carry over the previous `ciNewFailures` from `state.lastPrs` while the base is pending. A simpler alternative is to treat `undefined` as "don't flag" only for the pending-base case. Add an end-to-end `mapPr → classifyCard` test.

## Medium

- **M1. A failed enrichment throws away fresh discovery data.** Location: `server/refresh.ts:~420-428`. **(verified)**
  - Since the #72 batching, state, CI, draft flag and the base comparison come from discovery (`mapPr`). When `enrichPr` rejects (a 502 or throttle on the comments call), the whole fresh object is replaced by the `state.lastPrs` row.
  - Scenario: a PR goes from open with failing CI to merged. If the comments call fails, the board keeps showing it as open and failing in Needs Attention, and `merged_not_in_test` never fires. This lasts until enrichment succeeds.
  - Fix: keep the fresh object and copy over only `comments`, `reviewState` (unless the fresh value is `review_required`), `enriched` and `enrichedAt` from the fallback.

- **M2. Throttle backoff has no budget per refresh.** Location: `server/github.ts:~208-274`. **(verified, fake timers)**
  - `MAX_THROTTLE_WAIT_MS` caps each individual wait. With the primary limit exhausted (`x-ratelimit-remaining: 0`), every request waits 60s three times before failing, and nothing stops later requests from doing the same.
  - `fetchPrs` over 3 repos blocked for 9 simulated minutes, and enrichment adds about 3 more per batch. Refreshes are serialized, so `POST /api/refresh` and the tick loop stall behind it.
  - Fix: once one response shows the limit is exhausted, fail the rest of the sweep fast until the reset time, and/or set an overall deadline per refresh.

- **M3. `readBody` corrupts UTF-8 that is split across TCP chunks.** Location: `server/index.ts:24-31`. **(verified)**
  - `s += c` decodes each Buffer chunk on its own, so a multi-byte character that lands across a chunk boundary turns into `��`.
  - A long `/api/write` comment containing accents, emoji or smart quotes can be posted to Jira or GitHub corrupted.
  - The 1MB cap also counts UTF-16 units, not bytes.
  - Fix: collect the Buffers, check the byte total, and decode once with `Buffer.concat(chunks).toString('utf8')`.

- **M4. The Done page crashes the app when a Done card has a null `doneAt`.** Location: `web/src/done.tsx:10-11`, `web/src/types.ts:40`.
  - The server type is `doneAt: string | null` (`server/types.ts:234`), filled from `card.updatedAt`, which `iso()` sets to null when the timestamp is unparseable. The web type says `string`, and the sort calls `b.doneAt.localeCompare(...)`.
  - The row is persisted in `doneLedger`, so every visit to `/done` throws, and the ErrorBoundary's Retry throws again.
  - Fix: make the web type nullable and sort with `?? ''`, as `filed.tsx` and the server already do. The same type drift exists for todo/blocked `createdAt`.

- **M5. Auto-transition runs after the broadcast and is never re-broadcast.** Location: `server/index.ts:301-311`.
  - The tick broadcasts first, then transitions. A card that was just auto-moved still shows in Needs Attention for up to `refreshIntervalSeconds`, and a hidden tab gets a "needs attention" notification for it.
  - Fix: run the transitions before broadcasting and re-run the refresh when `succeeded > 0`.

- **M6. The incremental Filed list never drops deleted, moved or re-reported cards.** Location: `server/jira.ts:~199-204`, `server/refresh.ts:~334`. **(verified)**
  - The code comment says such cards linger "until the next full fetch (restart with an empty snapshot)". But the snapshot, including `filed`, is saved to `state.json` every tick and reloaded on startup, so a full fetch never happens again.
  - A card moved to another project (new key), or a change of `jira.accountId` or `baseUrl`, leaves the old rows in the list forever.
  - Fix: do a periodic full fetch (for example daily, tracked by a `filedFullFetchAt` stamp), and key the cached list by account and site.

- **M7. The docs contradict the code in several places.**
  - **Buckets after #91:** README "Buckets" and `docs/ARCHITECTURE.md:~122-123` still say an open PR with no review activity lands in `self_review`. Since #91, any non-draft open PR goes to `waiting_review`, or `mergeable` if approved.
  - **Done counter:** `docs/API.md:~149,234` and `ARCHITECTURE.md:~97-99,161` describe `doneTotal` as the current 14-day window and "not an all-time total". It is now `doneLedger.length`, fetched against a watermark.
  - **Automatic writes:** the README documents `autoTransitionMerged` and then says "Nothing in simon-dash writes to Jira or GitHub automatically or on a timer." `docs/API.md` and `config.example.json` don't mention the key.
  - **Simon runs:** the feature is undocumented. That covers `GET /api/simon/runs[/:id]`, the `simon` config block and the `/simon` route. `API.md` still says "Five endpoints".

## Low

### Server
- **L1. Prefix collisions in linking.** `server/link.ts:12-15` **(verified)**. `description.includes(p.url)` matches `/pull/1` inside `/pull/12`, and `body.includes('/browse/PROJ-1')` matches `PROJ-12`. Add a `(?![0-9])` boundary, as `mentions()` already has.
- **L2. Issue-comments request returns the oldest comments.** `server/github.ts:~383`. GitHub's issue-comments endpoint ignores `sort`/`direction`, so a PR with more than 100 comments (bots) returns the oldest 100 and newer human comments are missed. Use `since=` or follow `Link: rel="last"`. Checked against the API docs, not executed.
- **L3. The #92 own-reply watermark counts automated posts.** `server/classify.ts:~77-80`. It treats any comment by `myAccountId` as the user's reply, including comments posted through the dashboard's own MCP/CLI write-back. An agent's "PR updated" note silently answers a QA question. Fix: record the comment IDs posted by write-back and skip them.
- **L4. `/api/action` creates state for any key.** `server/actions.ts:~82`. It creates a `state.cards[key]` entry before validating the type or the key format, so arbitrary keys grow state without limit (local callers only). Validate first against `KEY_RE`.
- **L5. CLI argument parsing.**
  - `server/cli.ts:~80-84`: strict `parseArgs` over the whole argv means comment text containing `--json` or `-x` is stripped or rejected.
  - `pr-comment webapp#12` fails `REPO_RE` even though `config.repos` allows bare names.
- **L6. File permissions and the PID file.**
  - `state.json`, its `.bak` and `server.pid` are written with mode 0644 (default umask) and contain Jira summaries and comments. Write them with `mode: 0o600`.
  - `server/transport.ts:~18` writes the PID file in place. A reader that hits a half-written file reads "not running". Write to a temp file and rename.
- **L7. One subprocess per request.** `server/simon.ts:~89`: every `GET /api/simon/runs` spawns `simon status --json`. Cache the result for a few seconds.
- **L8. launchd restart loop.** With `KeepAlive`, `bin/start.sh` loops every 30s, rebuilding each time, if a hand-started server holds the port or the build fails.

### Web
- **L9. The SSE banner promises a retry that never happens.** `web/src/use-data.ts:~120` always says "retrying". After a 503 (the 32-client cap) or a 403, EventSource closes for good (`readyState === CLOSED`), so live updates stop silently. Show a "reload" message, or reconnect with backoff.
- **L10. Unguarded `localStorage`.** `web/src/app.tsx:~31-33,79` and the pre-paint script in `web/index.html` call `localStorage` without try/catch. If storage is blocked, the access throws during render.

## Checked and found sound

- **Refresh concurrency:** the seq-win block, serialization and the shared follow-up all hold.
- **`saveState` durability:** sound. M1 from 2026-08-08 is fixed.
- **ETag cache:** bounded.
- **Watermarks:** the Done/Filed date watermarks have a one-day lag that covers Jira's user-timezone evaluation.
- **`enrichConfirmed`:** the same-second recheck logic holds.
- **Host guard:** `guardHost` fronts every `/api/*` route, including SSE and Simon runs.
- **Mutating POSTs:** all three require JSON content type (simple-request CSRF is blocked). `/api/write` destructures its fields explicitly.
- **Path containment:** static files and Simon run IDs are both contained (`RUN_ID_RE`, resolve + startsWith, `%zz` returns 404).
- **Credentials:** none appear in logs or error paths. Upstream error bodies are truncated to 200 characters and auth headers are never echoed.
- **Auto-transition gates:** it shares the fail-closed config re-read, `writeEnabled`, demo refusal and project-prefix gates with `performWrite`. It runs only from the serialized tick, so it cannot double-fire.
- **MCP:** every write tool goes through `performWrite`, so it has the same gates as the dashboard.
- **Web:** no `innerHTML`/`dangerouslySetInnerHTML`. Every href comes from GitHub/Jira/config and uses `rel="noopener noreferrer"`. Chart.js instances are destroyed on unmount. All intervals and listeners are cleaned up. The confetti and notification first-event guards hold across `tick` frames. The Vite dev proxy passes the Host guard (probed).

Still deferred from earlier audits: SSE write backpressure (`server/index.ts`) and the a11y items.
