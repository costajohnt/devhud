## Verification of the previous audit's fixes

Checked directly against the current code, not taken on the remediation note's word. All sound:

- **H3 (stale broadcast)** — genuinely fixed, but *not* the way the audit prescribed. Rather than changing the call sites to `broadcast(state.snapshot)`, `refresh()` now returns `state.snapshot ?? payload` (`server/refresh.ts:290`, and `:226` for the demo branch), so a losing refresh hands its caller the *winner's* snapshot. Both call sites (`server/index.ts:168-171`, `:273-285`) keep passing the returned value, and are correct because of that. Better fix than the one proposed — the win/lose decision and the payload identity now live in the same place.
- **M8 (confetti replay)** — fixed and well-factored: the decision moved into a pure `applyEvent()` (`web/src/live-event.ts`) with a first-event guard, and `app.tsx:65` additionally gates on `newlyDone.length`, so a replayed snapshot can't fire the toast.
- **M9 (last-known-good clobber)** — `state.lastCards`/`lastPrs` now live inside the seq-win block (`server/refresh.ts:283-284`), gated on per-source `jiraOk`/`githubOk`.
- **M7 (console.log monkeypatch)** — replaced by a real `quiet` option threaded through `refresh()`; all three patch sites are gone.
- **M13 (overlapping ticks)** — self-rescheduling `setTimeout` armed only after completion (`server/index.ts:293`), with `unref()` and a `closed` flag.
- **M1 (write scope)** — `performWrite` now enforces project-prefix and repo-membership scope against the freshly re-read config (`server/writeback.ts:231-239`). The prefix check uses `startsWith(projectKey + '-')`, which correctly rejects the `PROJX-1`-vs-`PROJ` near-miss; repo membership reuses `fetchPrs`'s exact `owner/name` normalization, so the two can't drift.
- **Config validation, body cap, SSE client cap, nosniff/CSP, per-client broadcast isolation, `closed_at` mapping, `rel="noopener noreferrer"`, "Invalid Date" guard, `engines` (root)** — all present and correct.
- **Test-infra lows** — hardcoded ports replaced with `listen(0)`-then-release helpers (`server/cli.test.ts:19`, `transport.test.ts:24`), pid 999999 replaced with a cross-platform dead pid, and the SSE test reader now races a 5s rejection instead of hanging (`server/server.test.ts:468-475`).

The two prior HIGHs about coverage (H1 loop, H2 client SSE) are genuinely closed, not papered over — see **Test quality** below.

## High

### H1. Enrichment of last-known-good fallback PRs always fails with a bogus 404
`server/github.ts:188,199` (with `server/refresh.ts:248,252-254`). `enrichPr` ends with `delete pr._raw`, mutating the caller's object — and that same object is what `state.lastPrs` stores and `saveState` persists. On a later refresh where a repo's fetch fails, those `_raw`-less objects are spliced back in as the outage fallback (`refresh.ts:248`), linked (`:252`), and fed straight back into `enrichPr` (`:254`). For any **open** fallback PR the check-runs URL then interpolates a missing SHA: `/repos/o/r/commits/undefined/check-runs` → GitHub 404 → the whole `Promise.all` rejects.

**Verified by execution**, not just reading — a probe test calling `enrichPr` on a `_raw`-less open PR with a stubbed fetch asserts the request URL contains `/commits/undefined/check-runs` and that `enrichPr` rejects with a 404. It passed on the first run.

Failure trace: repo `o/r` has a transient GitHub outage on tick N. Fallback PRs are restored from `state.lastPrs` (correct behavior), but each open one now (a) burns 4 API calls of which the 4th is a guaranteed 404, (b) pushes `GitHub 404 /repos/o/r/commits/undefined/check-runs: Not Found` into `errors.github`, which the UI renders verbatim in the "GitHub fetch failed" banner, and (c) re-adds `o/r` to `degradedPrRepos` via `refresh.ts:263` — so ack-pruning stays disabled for that repo even in the sub-case where its PR data was actually intact. The fallback data itself survives (the rejection aborts before any assignment), so this degrades diagnostics, API budget, and ack behavior rather than board content. It compounds with M12's ETag work: the fallback path is exactly when the API budget matters most.

Fix (smallest): guard the check-runs branch on `pr._raw?.head?.sha` being present, keeping the existing `ciStatus` when it isn't. Better: don't re-enrich fallback PRs at all — they were already enriched on the refresh that cached them — or stop mutating the caller's object so `_raw` survives the round-trip. Note the same missing `_raw` silently weakens `reviewStateFrom` (`github.ts:198`) for closed fallback PRs, which lose the `review_required` signal without any error.

## Medium

- **M1.** Crash between the two renames in `saveState` loses all local state — `server/state.ts:96-100`. The sequence is `rename(path → path.bak)`, then write `path.tmp`, then `rename(path.tmp → path)`. Between the first and last rename there is no `state.json` at all. `loadState` treats a *missing* file as the normal first-run case and returns `emptyState()` immediately (`:74-75`) — it only consults `.bak` when the file exists but fails to **parse** (`:77-81`). So a crash, `kill -9`, or power loss in that window silently discards every override, ack horizon, celebration record, and the entire `prLog`, with a perfectly good `.bak` sitting right next to it. Fix: make the `.bak` rotation a copy (or do it after the tmp rename), and have `loadState` fall back to `.bak` on ENOENT too.

- **M2.** `docs/API.md` omits the entire error and hardening surface it claims to document. The file opens by calling itself the full reference for the local HTTP API, but nothing in it mentions: the `403 invalid Host header` DNS-rebinding guard that now fronts **every** `/api/*` route (`index.ts:136-139`), the `415` content-type gate on the three mutating POSTs, the `413 body too large` cap, the `503 too many event streams` cap at 32 SSE clients (`index.ts:147`), or the two new write-scope `403`s from M1's remediation (`writeback.ts:232,238`). A caller written from this doc gets surprised by five distinct rejections. Fix: one "Status codes" section, plus the two scope refusals in the existing `/api/write` gate list.

- **M3.** `docs/API.md:28` documents `/api/events` as "one `data:` line holding the full snapshot JSON" — the named `tick` heartbeat and broadcast suppression are entirely undocumented. That's the newest protocol behavior in the repo (`index.ts:112-116`), and it's load-bearing: a third-party client written from this doc renders a permanently frozen "Updated Xm ago" on an idle board, because the only event it ever sees again is one it doesn't listen for. The `web/` client handles it (`use-data.ts:113-119`); the spec doesn't.

- **M4.** CI tests only Node 26 while `engines` claims `>=22.18` — `.github/workflows/ci.yml:13` vs `package.json:12-14`. The floor the README makes a point of stating (and that native type stripping makes real) is never exercised, so a Node 22-incompatible syntax or API creeps in unnoticed. Fix: matrix `[22.18, 26]`.

- **M5.** `web/package.json` and `mcp/package.json` have no `engines` field — only the root does. Both are installed separately by the README's own three-step setup, and `mcp/` is explicitly documented as runnable standalone (`claude mcp add … node /path/to/simon-dash/mcp/index.ts`). A Node 20 user gets `ERR_UNKNOWN_FILE_EXTENSION` from the MCP server with no npm warning at install time — the exact failure M14 set out to eliminate, still reachable by the documented path.

- **M6.** Draft-PR routing outranks every attention trigger, and the README doesn't say so. `classify.ts:85-87` checks `pr.isDraft` **before** `visible.length`, so a draft PR with failing CI and three unread comments lands in Self Review Needed, is absent from Needs Attention, and is excluded from the tab-title count. This is deliberate and documented in `docs/ARCHITECTURE.md:110` ("always, even over attention triggers and overrides") — but the README states both the Needs Attention bucket rule and the Attention-triggers bullet with no exception, and the README is the entry point. Fix: one clause in the README; separately worth deciding whether red CI on a draft really should be silent, since the attention flags are still computed and rendered as a pill on the row.

- **M7.** `state.doneCelebrated` grows unbounded, and unlike `prLog` it isn't documented as such. `refresh.ts:100-102` appends per newly-Done card and nothing ever prunes. `docs/API.md:225` carefully calls out the same limitation for `prLog`; this one is invisible. Smaller per-entry than `prLog`, but it's in every `state.json` write forever.

## Low

- `server/jira.ts:100,135-146` — the `extraKeys` parameter is dead: no caller anywhere passes it (`refresh.ts:230` is the only call site). It also contains the last unescaped JQL interpolation in the codebase, `key in (${missingKeys.map(k => `"${k}"`).join(',')})`, which the config-validation batch didn't reach because it isn't config-sourced. Delete it, or validate before someone wires it up.
- `server/jira.ts:86` — `fetchLatestComments` interpolates `key` into the URL path unencoded, unlike `writeback.ts:73,91` which encode defensively for the same kind of key. Not attacker-controlled today (the key comes from Jira's own search response), so this is consistency, not exposure.
- `server/cli.ts:97` — `simon-dash open` hardcodes the macOS `open` binary with `stdio: 'ignore'` and no `'error'` listener. On Linux it prints `Opening http://localhost:3010`, exits 0, and opens nothing; **verified by execution** that the spawn raises `ENOENT` as an *unhandled* `'error'` event, which surfaces as a raw Node stack trace and exit 1 whenever anything delays the process exit past the error tick. Fix: platform-appropriate opener (`xdg-open`/`start`) plus an `'error'` listener that reports cleanly.
- `server/server.test.ts:543,568` — the two scheduled-loop tests run on real 1-second timers and account for ~5s of the suite's ~6s. The 5s per-event timeout leaves limited headroom on a loaded CI runner, where a tick plus assertions can drift. They are correct tests (see below); the cost and the flake surface are both real. Fake timers were the audit's original prescription and would remove both.
- `server/index.ts:117-126` — `broadcast()` ignores `write()`'s backpressure return value. The 32-client cap bounds the *number* of streams, not the per-stream buffer, so one stalled consumer still accumulates every future snapshot in heap. The cap made this much smaller; it didn't close it.
- `package.json:28` pins TypeScript `^7.0.2` while `web/package.json` pins `^5.7.0`, and root `tsconfig.json` `include` covers only `server/**` and `mcp/**`. So `npm run typecheck` never sees `web/src`, which is typechecked only by `cd web && npm run build` under a different compiler major. CI runs both, so nothing escapes there — but the local `npm test` loop gives false confidence on web changes.
- `web/tsconfig.json` includes `src` (so the three `*.test.ts*` files) but `web/package.json` doesn't depend on `vitest`; the build's `tsc` only resolves those imports by walking up to the root `node_modules`. Works in CI and locally, breaks the moment `web/` is built in isolation.
- `server/jira.ts:23` — `iso()` calls `new Date(t).toISOString()`, which throws `RangeError` on a malformed timestamp, failing the entire Jira fetch (and falling the board back to `lastCards`) over one bad field. Guard with `Number.isNaN(d.getTime())`.
- Carried forward, previously descoped by the owner: **M15** nested interactive control — `web/src/board.tsx:230-251` still renders a real `<a>` inside a `role="button"` row; **M16** detail-panel focus/Escape contract; and the `aria-live` announcement for successful moves. Unchanged by this audit's diff, listed so the ledger stays accurate.
- Still no lint script (`package.json:18-24`). The prior audit's example of what a linter would have caught (`rel` drift) was fixed by hand.

## Security summary

No new exposure, and the prior audit's one real gap is genuinely closed. Re-checked adversarially: the write scope check is correct on the near-miss cases (`PROJX-1` fails a `PROJ` prefix, lowercase `proj-123` fails, and repo membership normalizes `owner/name` identically to `fetchPrs`); it runs against the freshly re-read `liveConfig`, so it can't be bypassed by a caller holding a stale in-memory config; and it sits behind the fail-closed gate rather than in front of it. `guardHost` covers every `/api/*` route including SSE, `guardMutation` still holds the CSRF line via the non-safelisted content type, the body cap distinguishes 413 from 400, static responses carry nosniff + a CSP whose `unsafe-inline` limitation is honestly documented in-comment, and the prototype-pollution guard plus null-prototype `cards` remain belt-and-braces.

The ETag cache (`github.ts:115-137`) is safe on the aliasing question I went looking for: `cached.body` is handed back by reference on a 304, but every consumer copies (`mapPr`, `.map(comment)`) rather than mutating, and the `cached` binding is captured **before** the await, so a concurrent bulk-clear at the cap can't turn a 304 into the `GitHub 304 …` throw that the `!res.ok` line would otherwise produce. Keying by path alone is correct given one token per process.

Residual items are all LOW and all listed above: the dead `extraKeys` JQL path, the unencoded key in `fetchLatestComments`, and SSE write backpressure. The MCP trust boundary is unchanged and still correctly modeled — `UNTRUSTED_TEXT_NOTE` on both text-bearing payloads, and write tools now scope-limited, which is precisely the mitigation that matters for a prompt-injected agent.

## Test quality

The suite is in materially better shape than at the last audit, and the improvements are real rather than nominal — I checked each new test against the code it covers and against what regression it would actually catch.

- **The loop tests are honest tests.** `server/server.test.ts:543` proves both halves of H1's ask: tick 1 throws and the assertion `calls === 2` plus `updatedAt === 't2'` can only pass if the catch kept the loop alive; it also asserts the *shape* of the error log (full object, not a bare message). `:568` drives three ticks to distinguish "suppressed as a full snapshot" from "still heartbeats a `tick` frame" — that test fails if either half of the suppression logic breaks, which is exactly the property the feature rests on.
- **`use-data.test.tsx` earns its DOM environment.** It renders the real hook against a stubbed `EventSource` and covers the load-bearing cases individually: connect-replay vs fresh-refresh vs re-broadcast for `onRefreshed`, a deferred fetch proving an SSE frame supersedes an in-flight manual refresh, the `tick` path leaving the rest of the snapshot untouched, and a torn frame setting `connError` instead of throwing. These are the precise behaviors the audit called untestable without tooling.
- **ETag and write-scope both have targeted tests** (`github.test.ts:180`, `writeback.test.ts:331-363`), including the 304-serves-cache path and both scope refusals.

Remaining gaps, ranked: (1) **H1's fallback-enrichment path has no test at all** — no test drives a repo failure *and* a subsequent enrichment of the restored PRs, which is why a guaranteed 404 sits there unnoticed; (2) the ETag cache's eviction branch (`size >= MAX → clear()`) is untested, and it's the branch with the sharpest behavior; (3) `board.tsx`/`app.tsx` still have no component tests now that the DOM environment exists and the excuse is gone — the drop handler's payload construction is the highest-value target; (4) the two loop tests' real-timer cost/flake surface noted above.

## Refactoring map

Sequenced, smallest/highest-payoff first:

1. **H1 fallback enrichment** — guard the check-runs call on a present SHA and skip re-enriching restored PRs, plus the regression test in gap (1). Few lines; removes a guaranteed-failing API call from every degraded refresh.
2. **M1 `saveState` durability** — copy-instead-of-rename for `.bak`, and `.bak` fallback on ENOENT in `loadState`. Two small edits to one file, closes a silent total-state-loss window.
3. **Doc batch (M2 + M3 + M6)** — a Status-codes section, the `tick` event contract, and the README's draft-PR clause. No code risk, and M3 is the one that would actually mislead an implementer.
4. **Node floor (M4 + M5)** — CI matrix plus `engines` in the two sub-packages.
5. **Low sweep** — delete `extraKeys`, encode the comment-refetch key, `iso()` NaN guard, cross-platform `open` with an error listener.
6. **Lint script** — still the standing recommendation; item 5's kind of drift is what it prevents.

## Overall

The remediation work since 2026-08-06 held up under re-reading, including one fix (H3) that's better than the version prescribed. The live-update feature is now correct, covered, and cheaper per tick than when it landed. What this pass adds is one real bug in the *interaction* between two separately-correct features — outage fallback and enrichment, which each work fine alone and break when composed — one durability window in the oldest code in the repo, and a documentation surface that has drifted behind a fast-moving protocol. None of it is user-visible on the happy path; H1 and M1 both bite exactly when something else has already gone wrong.
