# simon-dash audit (2026-08-02)

simon-dash @ `7dff2b6`, branch `master`. Four parallel read-only review streams (correctness, security, tests, architecture), with every CRITICAL and HIGH finding sent to a fresh reviewer for adversarial verification before landing here.

Repo size: 16,179 tracked lines. Baseline was green before the audit started:

```
$ npm test
  (tsc --noEmit: clean)
  Tests  167 passed (167)
  Duration  647ms
$ cd web && npx tsc --noEmit
  (clean)
```

Stack: TypeScript Node server run directly via native type-stripping (no build step), Preact/Vite SPA, CLI, MCP server, and gated write-back to Jira/GitHub. Currently running in demo mode until real work credentials land.

## Critical

### C1. A card key of `__proto__` writes directly onto `Object.prototype`
`server/actions.ts:20` validates only `typeof key === 'string' && key`, then `server/state.ts:82-83` uses that key as a bracket-assignment property name: `state.cards[key] ??= {...}`. Because `__proto__` is an inherited accessor rather than an ordinary missing key, the read returns the live `Object.prototype`, which is not nullish, so `??=` never fires and never creates a fresh entry. `applyAction` then does plain assignments onto that reference (`cs.lastSeenPr = cs.lastSeenJira = horizon`, and for a move also `cs.override`/`cs.overrideAt`), which land as real own-properties on `Object.prototype` and are inherited by every plain object created for the rest of the process lifetime. The verifier reproduced it directly: `cs === Object.prototype: true`, then `({}).lastSeenPr === 'POLLUTED'`. Root cause is that the key guard was written to fix a data-hygiene bug (stray `"undefined"` entries) and therefore checks the key's type rather than its safety as a property name; a bracket-assignment sink needs a denylist or a null-prototype map. Reachable on all three surfaces with no filtering: `POST /api/action` with `{"type":"ack","key":"__proto__"}`, `simon-dash ack __proto__`, and MCP `ack_card` (whose schema is a bare `z.string()`), which means a prompt-injected Claude session can trigger it. Nothing persists to disk (inherited properties are not serialized), but a long-running server is poisoned until restart. Fix: reject `__proto__`, `constructor`, and `prototype` in the `actions.ts` guard, and make `state.cards` a null-prototype object as defense in depth.

## High

### H1. `GET /api/data` is exempt from the Host check, so DNS rebinding exfiltrates the whole board
`server/index.ts:68-70` returns the full snapshot with no call to `guardMutation` (`server/index.ts:35-46`), which is invoked only on the three mutating POST handlers at lines 72, 79, and 94. The guard bundles two different controls: a content-type check that defeats cross-origin CSRF, and a Host check that defeats DNS rebinding. It was scoped to mutating verbs because the threat model was CSRF, but rebinding attacks confidentiality on reads just as effectively. Binding to `127.0.0.1` does not help, which is the entire point of rebinding: the attacker's page keeps the origin string `evil.com` while its DNS re-points to loopback, so the browser considers the fetch same-origin, applies no CORS check, and the page reads the response body. That body is every card summary, Jira status, PR title and URL, up to ten comment bodies per card, plus merged and closed history, on a tab that is pinned all day. Fix: split the Host check into its own guard and run it on every `/api/*` route (and ideally the static handler), leaving the content-type check on POSTs only.

### H2. `config.json` holds long-lived Jira and GitHub credentials at mode 0644, with nothing in code or docs asking for 0600
`stat` confirms 0644 on both `config.json` and `config.example.json`; grepping `server/*.ts` for any mode-setting call returns nothing, and `server/config.ts` only ever reads the file. Those credentials are consumed directly: `server/jira.ts:90` builds Basic auth from `email` plus `apiToken`, and `server/github.ts` sends `token` as a Bearer header on every call. Root cause is that the threat model stops at the network boundary ("loopback only, single user"), so the one artifact holding long-lived secrets inherits the default umask like any source file. The verifier's refinement is worth stating plainly: this checkout's config is currently a demo placeholder, not live credentials, and on a genuinely single-account Mac 0644 versus 0600 changes little for that account's own processes. The exposure is real for other local accounts, other-user daemons, and backup or archive tooling that treats permissions as intent. Fix: `chmod 600 config.json` in the README setup step, plus a one-line warning from `loadConfig` when the mode is group- or world-readable.

## Medium

- **M1.** `mcp/index.ts` tool descriptions + `mcp/handlers.ts:35-37,179-188` — third-party Jira and GitHub comment text reaches Claude sessions as tool output with no delimiting or "this is data, not instructions" marking. The write tools got a careful behavioral gate for outbound actions; the inbound direction was never modeled. Fix: delimit untrusted text in the payload and say so in the tool descriptions and the README's Claude-integration section.
- **M2.** `.gitignore` (`data/*.json`) vs `server/state.ts:58` — the rotating backup writes `data/state.json.bak`, which the extension-enumerating ignore rule does not match; `git status` shows 24 KB of work card text untracked in the tree. Fix: ignore `data/*` with a `!data/.gitkeep` exception.
- **M3.** `launchd/com.johncosta.simon-dash.plist` — logs to `/tmp/simon-dash.log` (0644, shared directory) while the server logs every request and Jira issue keys. No credentials leak (auth headers are constructed inline and never logged), so this is work metadata exposure. Fix: log to `~/Library/Logs/simon-dash.log`.
- **M4.** `server/index.ts:130-132` — the catch-all 500 handler returns raw exception messages, so filesystem errors leak absolute paths to the client. One handler wraps both API and static branches, so it cannot tell authored messages from runtime ones. Fix: log the real error, return a generic message.
- **M5.** `web/src/chart-panel.tsx:59-83` — Monthly Activity chart mixes a local-calendar axis with UTC-keyed data buckets. `lastNMonths()` builds its six bucket keys from local `getFullYear()/getMonth()`, while `monthlyCounts()` buckets events by `at.slice(0, 7)`, the UTC year-month in the ISO string. At a large positive UTC offset an event can land one bucket earlier than the user expects, undercounting the current month and, at the window edge, dropping silently off the chart. Fix: generate the keys and bucket the data in the same time frame (either both UTC or both local).
- **M6.** `web/src/use-data.ts:17-41` — no request-ordering guard across `get()`, `refresh()`, and `act()`. `refreshInFlight` only stops two refreshes overlapping each other, so a slow `get()` resolving after a completed `refresh()` reverts the UI to the pre-refresh snapshot until the next 10-minute cycle. Fix: per-call sequence counter (or AbortController) with a staleness check at each `setData` site.
- **M7.** `server/refresh.ts:134-194` — concurrent `/api/refresh` calls have no ordering guard; the last `buildSnapshot()` to finish wins regardless of which fetched fresher data (two browser tabs, or CLI plus the web timer). Verified not a corruption risk: card state and the celebration tally survive either ordering, and `buildSnapshot` is synchronous end to end, so this is transient staleness that self-corrects next cycle. Fix: stamp each refresh with a monotonic sequence and skip the state write if a later one already completed.
- **M8.** `server/types.ts` vs `web/src/types.ts` — the payload contract is hand-mirrored in two packages and has already drifted on nullability (`NewComment.createdAt`, `Item.createdAt`/`updatedAt`, `MergedCard.pr`). Not a live bug (web assumes narrower than the server guarantees), but it is the evidence that nothing catches drift. Fix: one shared contract, or a test asserting key/shape agreement.
- **M9.** `server/index.ts:138-141`, `server/cli.ts:266-269`, `mcp/index.ts:20` — three entry points independently recompute the same repo-relative paths (config, state, pid, web/dist), duplicating logic `config.ts` already contains. Fix: a `resolveRepoPaths(moduleUrl)` helper used by all three.
- **M10.** `tsconfig.json` — no `noUnusedLocals`/`noUnusedParameters`, so several exported-but-unused interfaces (`ClassifyResult`, `CliResult`, `ErrorShape`, `ActionShape`, `WriteShape`, `CardCommentsShape`, `RefreshSummary`) sit unnoticed. Harmless today, one line to keep honest.

## Low (selected)

- `server/index.ts:117-127` — static path containment is checked lexically (`resolve` + `startsWith`) but the read follows symlinks, so a symlink inside `web/dist` escapes the root. Low because that directory is generated build output. Fix: compare `realpathSync` on both sides.
- `server/index.ts:128` — no `X-Content-Type-Options`, CSP, or `Referrer-Policy` on the SPA response. XSS risk is nil today (Preact escapes everything; no `dangerouslySetInnerHTML` anywhere in `web/src`), so this is defense-in-depth for the day a comment body gets rendered as markdown.
- `README.md` setup — uses `npm i` rather than `npm ci` for what is also the deployment path on a machine holding write-enabled credentials. Lockfiles themselves are properly pinned with integrity hashes.
- `server/cli.ts` (`open` command) — builds the URL from `config.port`, which `loadConfig` defaults but never type-checks, so a corrupted config yields an arbitrary URL passed to `open`. Fix: `Number.isInteger` validation in `loadConfig`.
- `docs/ARCHITECTURE.md:7-16` — module map missing `actions.ts`, `cli.ts`, `transport.ts`, `writeback.ts`, and has no MCP section at all despite ~420 lines and 8 tools there.
- `docs/ARCHITECTURE.md:42,118,124` — three stale `.js` references the TypeScript conversion's doc sweep missed.
- `server/index.ts:63-127` — the request handler is one 163-line if-chain. Earned today given the no-framework constraint (each endpoint is one `if` plus a guard call), but worth a dispatch table if a fifth or sixth endpoint lands.
- `server/index.ts:137` — the script-entry main guard (EADDRINUSE handling, pid file, SIGINT/SIGTERM) is untested. Mostly defensible, but the EADDRINUSE branch is real decision logic.

## Security summary

The controls added in the previous hardening round all hold at this commit and survived the TypeScript conversion intact: the mutation guard is applied to every state-changing POST, the write endpoint destructures its body explicitly rather than spreading it, the write gate re-reads config from disk and now fails closed, and the split-brain guard covers every direct-mode save. Credentials are handled correctly in flight: auth headers are constructed inline, never logged, never echoed back, and error bodies are truncated; a scan of the live `state.json` found no secrets and no raw API objects.

What is exposed is what the original threat model never covered. C1 is the sharpest: a key of `__proto__` walks straight through a type-only validator into a bracket-assignment sink and poisons `Object.prototype` for the process, reachable from HTTP, CLI, and an MCP tool whose schema is a bare string. H1 is the same class of gap one level up, where a control built for CSRF was scoped to writes while the read endpoint it also protects was left open to DNS rebinding. H2 is the local-file dimension the network-boundary threat model never considered. M1 completes the pattern: outbound LLM actions were carefully gated while inbound third-party comment text arrives at the model unmarked.

## Test quality

167 tests, all green, with genuine behavioral discipline in the pure layers: classification, linking, ADF construction, the write gate, and the transport guards are all covered by tests that assert real behavior rather than mocks, and the recent waves added regression tests for every fixed finding. The gaps are concentrated in the network and process edges.

1. `server/refresh.test.ts:6` — a module-level `vi.mock('./jira.ts')` makes `fetchJiraCards` reject for the entire file, so `refresh()`'s Jira-success path (`state.lastCards = cards`, `refresh.ts:150`) is never exercised. Breaking that assignment would not fail the suite.
2. `server/github.ts:111` — `fetchPrs` and `enrichPr` have no tests at all, not even with a mocked fetch, which is asymmetric with `jira.ts` where the equivalent function is tested that way. `enrichPr`'s comment merge and sort is real logic running unverified.
3. `server/writeback.ts:69` — the three functions that actually mutate Jira and GitHub have no direct tests of request construction or error branches. The tests cover the pure helpers and the gate that runs before dispatch, which is the safety-critical half, but not the dispatch itself.
4. `server/server.test.ts:61` — roughly fifteen tests share one mutable state object from a single `beforeAll` with no reset, so later tests depend on earlier mutations to card `P-1`. This passes only because the runner executes in declaration order; shuffling or parallelizing would break it non-deterministically.
5. `server/server.test.ts:200` — demo-mode `POST /api/refresh`, which is the actual first-run flow (guard, refresh, save, respond), is never exercised over real HTTP.
6. `web/` has no tests at all. The build-only gate is defensible for components, but `lastNMonths`, `monthLabel`, `monthlyCounts`, and `topRepos` in `chart-panel.tsx` are pure, DOM-free functions with real logic (and, per M5, a real bug) feeding the first thing a new user sees.
7. Smaller uncovered paths: `cardComments`' merged-card fallback (`mcp/handlers.ts:206`), the `serve` and `open` CLI commands (`server/cli.ts:91`), and the EADDRINUSE branch of the main guard.

## Refactoring map

Sequenced smallest and highest-payoff first.

1. **Guard hygiene (C1, M1)** — one denylist in `actions.ts` plus a null-prototype `state.cards`, and delimiting for untrusted text in the MCP payloads. Small diff, closes the sharpest finding.
2. **Split the two guards apart (H1)** — extract the Host check from `guardMutation` and apply it to every `/api/*` route. Small, mechanical, closes the exfiltration path.
3. **Local-artifact hygiene (H2, M2, M3)** — `chmod 600` plus a permission warning, a `data/*` ignore rule, and a plist log path under `~/Library/Logs`. Three unrelated one-liners that all shrink the local footprint.
4. **Path and contract deduplication (M8, M9)** — a `resolveRepoPaths(moduleUrl)` helper for the three entry points, and one shared bucket/payload contract so `server/types.ts` and `web/src/types.ts` stop drifting.
5. **Dual-transport at the operation level** — a `dualTransport({ http, direct })` helper in `transport.ts` replacing the eight hand-written copies of the same branching shape across `cli.ts` and `mcp/handlers.ts`. `performWrite` already proves the pattern works one level up; this is the largest single deletion available, on the order of 100 to 150 lines.
6. **Ordering guards (M5, M6, M7)** — same-frame chart bucketing, a request sequence counter in `use-data.ts`, and a refresh sequence stamp on the server. Related in shape, worth doing as one pass.
7. **Test gaps (1 through 6 above)** — unmock the Jira success path, cover the write-back dispatch and `fetchPrs`/`enrichPr` with mocked fetch, reset state between HTTP tests, and add the handful of pure chart-function tests.
8. **Doc accuracy** — the missing module-map entries, the absent MCP section, and three stale `.js` references in `ARCHITECTURE.md`.

## Feature opportunities (ranked)

1. **PR cycle time (S)** — `prLog` already carries `openedAt`, `mergedAt`, and `closedAt` per PR and is upserted every refresh, so time-to-merge and time-to-close are pure derivations with no new fetch and no schema change. A stat tile or a fourth chart series is nearly free.
2. **Stale-PR attention trigger (S)** — `classify.ts` extends cheaply, and the UI renders unknown attention reasons generically, so a "PR open N days with no review activity" trigger is one new condition using fields already on every PR, with zero web changes.
3. **Digest verb for CLI and MCP (S)** — `boardStatus` and `doRefresh` already return exactly the shape a morning briefing needs. A `simon-dash digest` command and matching MCP tool is glue over existing handlers, and it is the most direct expression of the always-on command-center framing.
4. **Weekly velocity or streak (S)** — every merge is already timestamped in `celebrated`, so a "this week versus last week" figure is a grouping over existing state.
5. **Time-in-needs-attention (S)** — `cardState` already timestamps `overrideAt`; adding a `firstFlaggedAt` on the same write path that `applyAction` already touches turns the attention buckets from a snapshot into a duration.
6. **Write-back audit trail (M)** — `performWrite` is the single choke point for every real mutation across all three transports, so appending `{type, target, timestamp, ok}` to a bounded ring buffer in `state.json` (the way `celebrated` already works) answers "what did I actually write" for almost nothing.
7. **Desktop notification on new needs-attention (M)** — `refresh()` already diffs to compute `newlyMerged`, and the confetti and toast path proves the notify-on-transition pattern end to end. The same diff over needs-attention keys is the second instance of an existing pattern rather than new plumbing.
